Nested Loop · Read the plan

Nested Loop
  Join Filter: (t.payee = m.account)
  Rows Removed by Join Filter: 8
  -> Seq Scan on demo_transactions t (rows=4 loops=1)
  -> Materialize (rows=3 loops=4)
       -> Seq Scan on demo_merchants m (rows=3 loops=1)
  • Outer side supplies four rows
  • Inner side is revisited four times
  • Materialize can cache the three merchant rows
  • Join condition rejects 8 of 12 candidate pairs

07 · Join order

A derived table is not magic

-- A: WHERE after JOIN
SELECT t.txn_id, m.category
FROM lab03_transactions t JOIN lab03_merchants m
ON t.payee_account = m.merchant_account
WHERE t.payer_account = 'u1001@bank';

-- B: pre-filter subquery (often same plan)
SELECT t.txn_id, m.category FROM
 (SELECT txn_id, payee_account FROM lab03_transactions
  WHERE payer_account = 'u1001@bank') t
JOIN lab03_merchants m ON t.payee_account=m.merchant_account;
For this INNER JOIN, PostgreSQL commonly pushes predicates down and produces the same plan.
POSTGRESQL · LAB 03 · JOIN OPTIMIZATION
07 · Join order

Be careful with LEFT JOIN

-- Preserves customers with no qualifying payment
SELECT a.account_id, t.txn_id
FROM lab03_accounts a
LEFT JOIN lab03_transactions t
  ON a.account_id = t.payer_account
 AND t.amount > 1000;

-- WHERE changes semantics: excludes unmatched accounts
SELECT a.account_id, t.txn_id
FROM lab03_accounts a
LEFT JOIN lab03_transactions t
  ON a.account_id = t.payer_account
WHERE t.amount > 1000;
Predicate movement across ON/WHERE is not always equivalent for outer joins.

09 · Aggregation

SQL · Direct vs pre-aggregated

/* A: Join then aggregate */
SELECT m.category, SUM(t.amount)
FROM lab03_transactions t JOIN lab03_merchants m
ON m.merchant_account=t.payee_account
GROUP BY m.category;

/* B: Aggregate by payee then join */
SELECT m.category, SUM(x.merchant_total)
FROM (SELECT payee_account, SUM(amount) merchant_total
      FROM lab03_transactions GROUP BY payee_account) x
JOIN lab03_merchants m
ON m.merchant_account=x.payee_account
GROUP BY m.category;
Pre-aggregation reduces join rows but adds an aggregate. It is not universally faster.

Detect temporary spills
